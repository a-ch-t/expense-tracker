# REVIEW.md

Правила ревью для этого репозитория — для человека и для Claude Code. Общие конвенции проекта
(команды, ветки, коммиты, TypeScript/ESLint) — в корневом `CLAUDE.md`, детали слоёв — в
`apps/api/CLAUDE.md` и `apps/web/CLAUDE.md`. Здесь только то, как проверять чужой (и свой)
диф перед вливанием.

## Что ревьюим

Единица ревью — **ветка целиком**, а не последний коммит: смотрим `git diff main`. Ревью
проходит после того, как ветка зелёная, и до `git push -u origin <ветка>` и PR.

Перед ревью из корня репозитория:

```bash
npm run build                    # он же пересобирает @expense-tracker/db
npm run lint
npm run typecheck
npm test -w @expense-tracker/api
```

Красная ветка на ревью не выносится: замечания «не собирается» и «падает тест» автор снимает
сам. Если `typecheck` ругается на `@expense-tracker/db` (`has no exported member ...`) — это не
замечание к коду, а не пересобранный `dist/`: `npm run build -w @expense-tracker/db`.

## Формат замечания

Замечание — это **место, суть и причина**: ссылка вида
`apps/api/src/transactions/transactions.service.ts:42`, что не так, почему это ломается и что
сделать. «Мне бы больше понравилось иначе» — не замечание.

| Уровень      | Что значит                                                  | Что делать              |
| ------------ | ----------------------------------------------------------- | ----------------------- |
| **Блокер**   | Ломает поведение, безопасность или инвариант из `CLAUDE.md` | Правим до вливания      |
| **Важное**   | Работает, но заведёт на грабли следующего                   | Правим или объясняем    |
| **На выбор** | Улучшение, автор решает сам                                 | Можно оставить как есть |

Автор отвечает на каждое замечание: исправил или почему не согласен. Молча закрытая ветка —
плохой ответ.

## Общее (весь монорепозиторий)

- **Новых зависимостей в дифе быть не должно**, если о них не договаривались отдельно. Появился
  пакет в `package.json` — просим обоснование.
- **TypeScript не поднимаем** — версия закреплена на 5.9.3 требованием `@nestjs/cli`.
- **`any`, `as unknown as` и `@ts-expect-error` — повод для вопроса.** Со `strict` и
  `noUncheckedIndexedAccess` индексный доступ и `process.env['X']` дают `T | undefined`, и это
  обрабатывают явно, а не глушат приведением. Исключение — моки в тестах.
- **Неиспользуемые переменные** допустимы только с префиксом `_`; всё остальное поймает ESLint.
- **Комментарии на русском и про «почему», а не про «что»**. Комментарий, пересказывающий
  следующую строку, — лишний. Неочевидное решение (`onDelete: Restrict`, обход правил импортов,
  порядок workspace) объясняем в коде или в теле коммита.
- **Форматирование не обсуждаем** — это работа Prettier (одинарные кавычки, `printWidth: 100`,
  `trailingComma: all`).

## apps/api

**Границы модулей**

- `auth`, `users`, `categories`, `transactions` не импортируют друг друга — только через
  `contracts/*` и `common/*`. Обход `no-restricted-imports` в дифе — блокер.
- Импорт из общих слоёв только через барель (`'../contracts/users'`), а не по прямому пути.
- У таблицы ровно один владелец (`users` → `User`, `categories` → `Category`,
  `transactions` → `Transaction`). Чужие данные читаются через `CommandBus`/`QueryBus`, а не
  прямым обращением к `PrismaService`.
- Тип, который понадобился соседнему модулю, переезжает в `contracts/`, а не экспортируется из
  модуля-владельца.

**Безопасность и владение данными**

- Новый эндпоинт закрыт `JwtAuthGuard`, если это не публичные `register`/`login`/`health`.
- `userId` берётся из `@CurrentUser`, **никогда** из тела запроса, query или параметра пути.
- Каждый запрос к БД фильтрует по `userId`: `findFirst({ where: { id, userId } })`,
  `update({ where: { id, userId } })`. `findUnique` по одному `id` в дифе — блокер.
- Чужой ресурс отдаёт **404, а не 403**: существование чужих записей не подтверждаем.
- Валидный токен несуществующего пользователя — 401. Это делает `JwtAuthGuard` один раз на все
  закрытые эндпоинты; повторная проверка владельца в сервисе — лишний запрос и повод убрать её.
- Пароли, хеши и `JWT_SECRET` не попадают в ответы, логи и read-модели. `bcryptjs` знает только
  `auth`.

**Слои модуля**

- Контроллер — только маршрут, DTO и `@CurrentUser`; логика в сервисе, SQL — в репозитории.
- Репозиторий возвращает read-модель, а не сущность Prisma; `Decimal` превращается в `number`
  на этой же границе.
- DTO — класс с декораторами `class-validator` (глобальный `ValidationPipe` с
  `whitelist + forbidNonWhitelisted + transform`); значения по умолчанию задаются
  инициализаторами полей, а не в сервисе.
- Ошибки Prisma не текут наружу: `P2002` → 409, `P2025` → 404, `P2003` при удалении
  категории → 409 («держат транзакции»). Голый `PrismaClientKnownRequestError` в ответе — блокер.
- Периоды считаются полуинтервалом `[gte, lt)` в UTC — без локальной таймзоны сервера.
- Агрегаты и `total` считаются по всему периоду, а не по странице.

## apps/web

- **Зависимости идут строго вниз** по цепочке
  `app → views → widgets → features → entities → shared`. Импорт вбок (слайс из слайса того же
  слоя) — блокер.
- Снаружи слайс импортируется через свой `index.ts`; `shared` — наоборот, посегментно
  (`@/shared/ui/button`), барель на весь слой не заводим.
- **Запросы к API идут только из серверного кода** через `apiFetch`. `API_URL` без
  `NEXT_PUBLIC_`; появление `fetch` к бэкенду в клиентском компоненте — блокер: токен лежит в
  httpOnly-куке.
- **Ответ API различает «отказано» и «не смогли спросить».** Состояние вида
  `ok | unauthenticated | unavailable` обязательно: `unauthenticated` уводит на `/logout`,
  `unavailable` не редиректит вовсе. Редирект на `/login` при любой ошибке — блокер, он даёт
  цикл с `proxy.ts`.
- Куку ставит и снимает Server Action или роут; имя и опции — только из
  `shared/config/session-cookie.ts`.
- Новый закрытый раздел — три правки: страница внутри `src/app/(app)/`, путь в `ROUTES`, он же
  в `matcher` и `PRIVATE_ROUTES` в `src/proxy.ts`. Забытый `proxy.ts` — типичная дыра.
- `'use client'` — только там, где нужен браузерный рантайм (состояние, обработчики,
  `usePathname`). Компонент, ставший клиентским ради вёрстки, — замечание.
- Суммы и даты форматирует `shared/lib/format.ts`; колонки цифр — с `tabular-nums`. Свой
  `toLocaleString` в компоненте — замечание.
- Знак операции красится `text-income` / `text-expense`, не `chart-*`.
- Компоненты shadcn ставятся в `@/shared/ui`. Тяжёлый готовый компонент ради статичного
  блока — повод спросить, нужен ли он.

## packages/db

- Правка `schema.prisma` приходит вместе с миграцией в `prisma/migrations/`.
- `onDelete` выбран осознанно и объяснён: `Cascade` — для данных пользователя, `Restrict` — там,
  где удаление уносило бы историю.
- `@prisma/adapter-pg` остаётся только в `packages/db/src/index.ts`; потребители импортируют
  `@expense-tracker/db`.
- `src/generated/` и `dist/` в дифе быть не должно.

## Тесты

- Тесты есть только у API — `*.spec.ts` рядом с кодом, уровень сервиса: репозиторий и
  `QueryBus`/`CommandBus` мокаются.
- Новая ветка ошибок (401 / 404 / 409) без теста — замечание.
- Багфикс без теста, который падал бы до правки, — замечание.
- Тест проверяет поведение (код ошибки, содержимое ответа), а не то, что мок был вызван.

## PR

- Заголовок PR — по Conventional Commits: `<тип>(<область>): <что делает>`, императив, без
  точки, до 72 символов.
- Описание отвечает на два вопроса: **что реализовано** и **какие эндпоинты добавлены или
  изменены** (метод, путь, коротко о каждом) — и составлено по `git diff main`, а не по памяти.
- В дифе нет мусора: `.env`, `dist/`, `.next/`, `.DS_Store`, закомментированного кода и
  отладочных `console.log`.
- Ветка вливается `--no-ff`, после вливания удаляется вместе с worktree.

## Что замечанием не считается

- Стиль, который не ловят Prettier и ESLint, — вкусовщина.
- Сгенерированное и служебное: `packages/db/src/generated/`, `dist/`, `.next/`, блок
  `nextjs-agent-rules` в `apps/web/AGENTS.md` (его переписывает `next dev`).
- «Я бы написал иначе» без выигрыша в поведении, читаемости или безопасности.
- Работа, которую автор явно вынес за рамки задачи и назвал в описании PR.
