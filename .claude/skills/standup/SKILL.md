# standup

## Overview

Собирает коммиты текущего пользователя за вчерашний день по всем локальным веткам и
превращает их в детальный отчёт «что было сделано» — для устного стендапа. Вызывается только
вручную (`/standup`), модель сама этот скилл не подключает.

## Диапазон «вчера»

Платформа — macOS (Darwin), поэтому даты считаются через BSD `date`:

```bash
since=$(date -v-1d +%Y-%m-%d)
until=$(date +%Y-%m-%d)
```

`since` — вчерашняя дата, `until` — сегодняшняя: половина открытого интервала `[00:00 вчера,
00:00 сегодня)` покрывает вчерашний день целиком независимо от того, в какой момент запущен
скилл.

## Сбор коммитов

Смотреть по **всем** веткам (`--all`), а не только по текущей: в GitHub Flow (см. корневой
`CLAUDE.md`) работа за день обычно лежит в отдельной feature-ветке, а не в `main`. Фильтр по
автору — текущий git-пользователь, иначе в отчёт попадут чужие коммиты из общих веток.

```bash
author=$(git config user.name)
git log --all --author="$author" \
  --since="$since 00:00:00" --until="$until 00:00:00" \
  --date=format:'%H:%M' --pretty=format:'%H|%h|%ad|%s'
```

Если список пуст — сообщить, что за вчера коммитов от этого автора нет, и на этом остановиться,
не выдумывая отчёт.

## Детализация каждого коммита

Для каждого хеша `%H` из списка выше:

```bash
git log -1 --format=%b <hash>          # тело коммита — «зачем»
git show --stat --format='' <hash>     # какие файлы затронуты
```

Тело коммита раскрывает мотивацию (в этом репозитории тело коммита обязано отвечать на
«почему», см. скилл `commit`), список файлов — масштаб изменения. Merge-коммиты (`Merge pull
request #N ...`) не имеют собственного постатейного диффа — это нормально, в отчёте они
отмечаются как «влита ветка X» по теме коммита.

## Формат отчёта

Группировать по веткам/задачам, а не просто списком коммитов подряд — на стендапе рассказывают
по задачам:

```markdown
## Стендап — <дата вчера>

### <ветка или задача>
- **<заголовок коммита>** (`<короткий hash>`, <время>)
  <тело коммита, если есть — переформулировать как факт, а не копировать дословно>
  Файлы: <file1>, <file2>, ...
```

В конце — короткий итог: сколько веток/задач затронуто, есть ли влитые PR.

## Быстрая справка

| Вопрос                          | Ответ                                                |
| -------------------------------- | ----------------------------------------------------- |
| За какой период                 | Вчера целиком, `[00:00 вчера, 00:00 сегодня)`        |
| По каким веткам                 | По всем локальным (`--all`)                          |
| Чьи коммиты                     | Только текущего `git config user.name`               |
| Источник причины изменения      | Тело коммита (`%b`)                                  |
| Источник масштаба изменения     | `git show --stat`                                    |
| Пустой результат                | Явно сказать «коммитов не было», не придумывать отчёт |
| Как вызывается                  | Только вручную, `/standup`                           |

## Частые ошибки

- Забыть `--all` — тогда не видно работы в feature-ветках, если сейчас `git checkout main`.
- Не отфильтровать по автору — в отчёт попадут чужие коммиты с общих веток.
- Пересказать только заголовки коммитов без тела — отчёт получится «что», а не «зачем», а
  стендап держится именно на «зачем».
